# Kairema v5 — проектирование данных и контекстов

## Принцип изоляции

Все новые сущности привязаны к `userId`. Получение, изменение, удаление и формирование контекста выполняются только через server-side функции, которые сначала подтверждают владение текущего пользователя. Ключи, upstream model ID, скрытые fallback-цепи, полные системные prompts и служебные причины отказа не становятся частью публичных ответов.

| Сущность | Назначение | Изоляция и ограничение |
|---|---|---|
| `user_settings` | Язык интерфейса, тема, ответный стиль, длина, быстрые ответы, effort, thinking, default role и web-search preference | Один профиль на пользователя, первичный ключ `user_id` |
| `memory_profiles` | Включение памяти, автоизвлечение, пользовательский профиль и составленная сводка | Один профиль на пользователя; только очищенный текст |
| `memory_facts` | Отдельные подтверждаемые факты пользователя | Только `userId`; максимум 280 символов на факт |
| `chat_attachments` | Метаданные приватного объекта S3, тип, размер, extracted text и готовность | Проверяется и владелец, и чат; байты не хранятся в БД |
| `messages.metadata` | JSON с публичными ссылками web-search и описанием вложений, привязанных к сообщению | Не содержит ключей, upstream ID или скрытых маршрутов |

## Серверный контекст чата

Перед ролью создаётся только следующий проверяемый контекст: системная личность Kairema, применённые настройки пользователя, компактная память (если включена), текстовая выжимка принадлежащих чату документов и при включённом доступном web-search — grounded research с фактическими источниками. Полный файл, скрытая цепочка ролей, ключи и внутренние диагностические сообщения в prompt не передаются.

Изображения обрабатываются отдельным мультимодальным сообщением и только когда актуальный server-side кандидат поддерживает vision. При недоступности vision-провайдера интерфейс сохраняет файл как вложение, но до отправки явно сообщает, что анализ изображения сейчас невозможен. Текстовые документы продолжают работать через извлечение текста.

## Web-search

Режим использует Google Search grounding server-side. Ответ попадает в модельный контекст только после успешного результата и в интерфейс только с фактически возвращёнными заголовками и URL. Живая проверка среды зафиксировала текущую Google quota-ошибку, поэтому UI обязан отключать недоступный переключатель и не создавать фиктивные цитаты. Формат grounding metadata и источников описан в официальной документации Google [1].

## Управление памятью

Автоизвлечение запускается после успешно сохранённого ответа. Отдельный строгий server-side вызов может предложить не более трёх кратких фактов, основанных только на последнем сообщении пользователя. Невалидный JSON, технические данные, инструкции, секреты, финансовые реквизиты и дубликаты отбрасываются. Пользователь в любой момент может отключить память, выключить автоизвлечение, удалить отдельный факт, изменить профиль или полностью очистить память.
