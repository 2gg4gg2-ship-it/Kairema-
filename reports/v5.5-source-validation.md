# Kairema v5.5 — проверка внешних API

Дата проверки: 19 августа 2026 г.

| Сервис | Подтверждённый контракт | Решение для Kairema |
|---|---|---|
| Google Gemini Grounding | Google рекомендует Interactions API; для актуальных моделей используется tool `google_search`. Ответ возвращает inline `url_citation` с URL, названием и диапазонами текста. | Сохранить Google как primary только там, где политика роли разрешает live search. Извлекать реальные URL/названия в источники; старый `google_search_retrieval` не добавлять для новых моделей. |
| Tavily Search | `POST /search`, `Authorization: Bearer <api-key>`; ответ содержит массив `results` с `title`, `url`, `content` и оценкой. | Использовать только server-side и только при наличии ключа; при 429 Google получать проверяемые URL из `results`, а не показывать сгенерированное поле `answer` как источник. |
| Mistral | Chat Completion использует `POST /v1/chat/completions`; API требует допустимый `model` из List Available Models. | Не фиксировать Codestral ID без проверки серверного каталога на старте или перед запросом. Неразрешённую/недоступную модель пропускать, а не показывать в UI. |
| SambaNova | Официальная документация описывает OpenAI compatibility и отдельный каталог моделей SambaCloud. | Передавать стандартные OpenAI-совместимые сообщения только server-side. Перед добавлением резерва подтвердить Model ID через `GET /v1/models`; при ошибке пропустить SambaNova. |

## Запланированная совместимость

Ни один секрет не будет появляться в клиентском bundle, сообщениях об ошибках или отчётах. Новые сервисы остаются необязательными: без ключа они не изменяют четыре видимые роли, их текущие primary/fallback-цепи или уже проверенный RAG v5.3.

Отдельный Vitest health-check подтвердил работу защищённых полей без журналирования значений: Tavily `POST /search`, SambaNova `GET /v1/models` и Mistral `GET /v1/models` ответили успешно. Это подтверждает server-side доступность, а не раскрытие ключей.

## Живые каталоги моделей

Проверка server-side каталогов подтвердила доступность следующих разрешённых ID на дату отчёта: OpenRouter — `poolside/laguna-s-2.1:free`, `cohere/north-mini-code:free`, `nvidia/nemotron-3.5-lightning:free`, `nvidia/nemotron-3-super-120b-a12b:free`, `nvidia/nemotron-3-nano-30b-a3b:free` и `nvidia/nemotron-nano-9b-v2:free`; SambaNova — `Meta-Llama-3.3-70B-Instruct` и `gemma-4-31B-it`; Mistral — `codestral-2508` и `codestral-latest`. В реализации будет использован только ограниченный набор из этого подтверждённого перечня, с автоматическим пропуском недоступного провайдера.

## Живая проверка search fallback

Проверка `gemini-3.6-flash` с `google_search` вернула HTTP `429`, то есть quota-ветвь обработана как реальная недоступность, а не как успешный поиск. Следующая server-side проверка Tavily вернула HTTP `200`, поле `results` и три уникальных URL. В проверку не попадали ответы «answer» Tavily, значения ключей или содержимое приватных запросов.

Итоговая v5.5 регрессия: 23 test files, 68 tests, TypeScript и production build пройдены; desktop 1280×720 и mobile 375×812 подтверждены во встроенном браузере.
