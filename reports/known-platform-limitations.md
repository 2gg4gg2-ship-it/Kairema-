# Kairema — подтверждённые ограничения платформы и внешнего доступа

**Статус документа:** 20 августа 2026 года. Этот документ закрывает только анализ и корректное решение по ограничениям. Он не представляет отсутствующую функциональность как реализованную.

| Область | Подтверждённое ограничение | Принятое безопасное решение | Условие пересмотра |
|---|---|---|---|
| Физическое удаление экспортов из S3 | Текущий адаптер хранилища предоставляет загрузку и выдачу защищённых ссылок, но не предоставляет server-side delete API. | Экспорт удаляется логически: owner-scoped запись и UI-ссылка исключаются. Физический DELETE, фальшивый progress и неподтверждённые retry не реализуются. | Платформа документирует и предоставляет официальный delete helper. |
| Ежедневный Heartbeat health | Платформа доставляет heartbeat только на опубликованный production URL; dev sandbox недоступен для cron. | Защищённый cron-only endpoint и idempotent health-логика сохранены в коде. Задание не создаётся до публикации, поскольку агент не публикует проект самостоятельно. | Владелец публикует checkpoint и запрашивает подключение расписания. |
| ZenMux как active fallback | После защищённой замены ключа три свежие completion-пробы дали 402, 429 и 200. Политика Kairema требует три HTTP 200 до изменения active allowlist или цепей. | ZenMux остаётся health-only. В публичном UI нет ложного статуса готовности, а первые четыре кандидата ролей не меняются. | ZenMux предоставляет доступ, после чего выполняются три новые server-side completion-пробы. |

> **Инвариант:** ограничения не обходятся альтернативным неофициальным API, не компенсируются выдуманными статусами и не снижают приватность, доступность либо ограничение четырёх upstream-попыток.
