# Kairema v4 — отчёт живой приёмки

**Дата проверки:** 19 августа 2026 года.  
**Область:** четыре публичные роли, общий PROVIDER_HEALTH, безопасный fallback, streaming и клиентская изоляция секретов.

## Результат живых server-side запросов

Запросы отправлены одновременно из server-side сценария `scripts/live-v4-acceptance.mts`. В момент проверки OpenRouter имел подтверждённое ограничение квоты (HTTP 429), поэтому каждая роль безопасно пропустила общий заблокированный провайдер и использовала доступный резерв Groq. Ключи, URL с авторизацией и скрытые fallback-цепочки в отчёте не приводятся.

| Роль | Primary-кандидат | HTTP | model_used | Статус |
|---|---|---:|---|---|
| Быстрый | GPT-OSS 20B | 200 | GPT-OSS 20B | Резерв активен |
| Смекалистый | Gemma 4 26B | 200 | GPT-OSS 120B | Резерв активен |
| Контекст | Nemotron 3 Ultra | 200 | GPT-OSS 120B | Резерв активен |
| Флагман | Gemma 4 31B | 200 | GPT-OSS 120B | Резерв активен |

Все четыре роли вернули непустой текст. Успешный ответ резерва обозначается честным статусом **«Резерв активен»**; интерфейс не выдаёт его за primary-кандидат.

## Контролируемый quota-429 и общий health

Unit-сценарий `marks a quota-limited provider globally so another role skips it` в `server/providers.test.ts` намеренно возвращает OpenRouter HTTP 429 с quota-классификацией. Проверка подтверждает два свойства: событие записывается в общий `PROVIDER_HEALTH` по ключу провайдера, а следующая роль пропускает OpenRouter до истечения cooldown либо до успешного server-side ping. Это исключает повторные запросы к уже заблокированному источнику для разных ролей.

> Сброс `blockedUntil` не происходит от браузерного действия: его может произвести только успешная server-side перепроверка провайдера.

## Контекст и Флагман — сравнение назначений

| Критерий | Контекст | Флагман |
|---|---|---|
| Основное назначение | Большие тексты, история диалога и глубокий анализ | Сложные задачи, переводы и максимальная мощность |
| Предпочтительный результат | Сохраняет нить длинного обсуждения и структурирует объёмный материал | Ставит качество решения сложной задачи выше скорости |
| Общее поведение при outage | Использует безопасный кросс-провайдерный резерв, не смешивая ответ нескольких моделей | Использует безопасный кросс-провайдерный резерв, не смешивая ответ нескольких моделей |
| В интерфейсе | Постоянная русскоязычная карточка «Kairema Контекст» | Постоянная русскоязычная карточка «Kairema Флагман» |

## Ограничение публикации

Код защищённого endpoint `/api/scheduled/provider-health` и server-side стартовой проверки готов. Создание ежедневного project-level Heartbeat возможно только после публикации приложения; до публикации endpoint не должен быть вызван внешним планировщиком.
