# Kairema — реализация требований к надёжности поиска

**Дата:** 2026-08-25 (GMT+3)  
**Область:** только search pipeline, публичное evidence и честная политика свежести.  
**Исключено из работ:** ключи и переменные окружения, owner mapping, OAuth, история, память, пользовательские вложения, модельные цепочки и лимит попыток вне search cascade.

## Что реализовано

| Требование | Реализация | Статус |
|---|---|---|
| Не выдавать старые данные за свежие | Введена query-specific проверка свежести. Для новостей, текущей погоды, «последних», «новых» и аналогичных запросов недатированный либо просроченный источник не считается подтверждением актуальности. | **PASS (source/test)** |
| Честный fallback | Если подходящего свежего источника нет, в ответ попадает безопасный `freshnessBlocked`-статус и интерфейс показывает «Живой поиск недоступен». Модель получает инструкцию не имитировать поиск и не отвечать устаревшими данными как актуальными. | **PASS (source/test)** |
| Реальные ссылки | Через SSE и persisted message metadata передаются только whitelisted public title, URL и публикационная дата фактически полученного web-источника. Внутренние provider/RAG данные и технические причины отказа не передаются в UI. | **PASS (source/test)** |
| Каскад | Активный серверный порядок: **You → Serper → Exa → Tavily**. Tavily добавлен последним проверенным fallback-слоем; суммарный предел остаётся **не более 4 upstream attempts**. | **PASS (source/test)** |
| Последовательность и история | Изменение search metadata не затрагивает опубликованный инвариант: durable extraction темы выполняется до клиентского SSE `done`. | **PASS (regression)** |

> **Принцип ответа на свежий запрос:** либо показываются реальные полученные источники с публичной датой и доменом, либо пользователь получает явное ограничение «Живой поиск недоступен». Синтетические ссылки, даты, поисковые результаты и источники не создаются.

## Ограничения live acceptance

Исходный код и тесты подтверждены. Реальная authenticated browser-приёмка не выполнялась: она остаётся **NOT VERIFIED BY PLATFORM SESSION** по ранее зафиксированному ограничению. Canonical `lkn.manus.space` ранее отдавал platform maintenance/503 вместо Kairema и остаётся **BLOCKED BY PLATFORM DELIVERY**, пока платформа не начнёт доставлять актуальный runtime. Поэтому этот документ не заявляет live PASS для пользовательского браузерного сценария.

## Изменённые границы

Изменения ограничены `server/web-search.ts`, `server/chat-context.ts`, `server/chat-stream.ts`, `server/providers.ts`, клиентским SSE-normalizer, Home metadata parser и AIChatBox. Одноразовые диагностические сценарии были удалены до публикации и не входят в production runtime.
